# Project Milestone 2.1: Development Sprint I

This project milestone will focus on setting up your development workflows and starting the development of your system.

### Feature Implementation

You must create a fork of the original Project 1 repository and make contributions to your team's version of the codebase for your project. There is nothing to submit on Canvas for the Feature Implementation, but the following will be evaluated on your Project 2 GitHub repository at the end of the Sprint:

**Project Management**

You must use GitHub Projects to manage project tasks. Tasks must be assigned to individual team members and using columns to track progress for each sprint.


**Testing**

Generate unit tests for any function(s) implemented for PM2.1 (at least one unit test per function, or if applicable---at least one integration test incorporating multiple functions working together). You may use AI to generate the tests, and must adhere to the course AI policy (comment tests generated by AI with prompts and/or provide log, etc.). The tests should be added to your repository.

**Code Review**

For major code contributions, please submit a pull request to the repository (for simple changes, pushing directly to the repo is ok). The code may be generated by a teammate or by AI, adhering to the class and team AI policies. In the pull request, please add an appropriate title, comment, etc. A peer code review must be conducted for each pull request to your repository. A team member should review a segment of code submitted by another teammate (AI- or human-generated, but not their own PR) and provide a brief review describing the following items:

* Overview: General comment summarizing the review.

* Correctness: Does the code work for the intended purpose?

* Quality: Is it readable and understandable?

* Maintainability: Does it follow normal coding and style conventions?

* AI-Specific Concerns: If AI was used, explain what issues were found in AI-generated code and potential lessons learned about relying on AI for implementation.

* Recommendation: A final outcome for the PR: merge as is, close, return for changes, etc.

### Progress Report

You must include a brief report summarizing a retrospective of the current milestone and sprint planning of prioritized tasks for the next milestone. Please upload this to Canvas or clearly describe in your repository where the progress report is located.
